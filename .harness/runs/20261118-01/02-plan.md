# 02. 기획 — 예약 신청 개선 (B·C·D·E)

- 실행 ID: 20261118-01 / 작성: planner / G1 승인 코멘트: "범위 B,C,D,E 로 진행 (A 요금·환불 섹션, F RLS 축소는 제외)"

## 1. 목표 / 비목표
**목표**
- B. 예약 신청 시 개인정보 수집·이용 동의를 받고, 개인정보처리방침 페이지를 공개한다.
- C. 예약 신청 폼이 실제 운영 규칙(평일 07:00–22:00, 토·일·공휴일 휴무, 이미 찬 시간)을 반영하고, 수업 종류·요청사항을 받는다.
- D. 예약·취소 규정을 신청 전에 고지한다 (예약 모달 + FAQ).
- E. 관리자가 승인/거절 직후 신청자에게 보낼 안내 문자를 원클릭으로 작성·복사할 수 있다.

**비목표 (이번에 하지 않음)**
- A 요금·환불·보증보험 공개 섹션 (승인권자 제외 — 단, 법적 의무 항목이므로 다음 실행 권장)
- F anon 의 reservations 컬럼 축소 (승인권자 제외)
- 알림톡/자동 문자 발송, 회원 로그인, 대기 예약, 온라인 결제

## 2. 사용자 시나리오
- **방문자(PC/모바일)**: '수업 예약' → 모달에서 수업 종류 선택 → 날짜 선택(주말·공휴일이면 즉시 안내) → 해당 날짜의 가능 시간만 선택 가능(마감 시간은 "마감" 표시) → 이름·휴대번호·요청사항 입력 → 예약·취소 규정 확인 → [필수] 개인정보 동의 체크(전문 보기 / 처리방침 링크) → 신청 → 완료 화면에 "확인 후 문자로 안내" 표시
- **관리자(admin.html)**: 대기 요청 카드에서 수업 종류·요청사항까지 확인 → 승인/거절 → 안내 문자 창(미리 채워진 문구, 수정 가능) → [문자 보내기](모바일: 문자앱 열림) 또는 [문구 복사](PC)
- **정보주체**: 사이트 하단 '개인정보처리방침' 링크 → /privacy 에서 처리 내용·문의처 확인

## 4. 수용 기준 (Acceptance Criteria)
- **AC-1** 개인정보 동의 체크 없이는 신청 버튼이 동작하지 않고 안내 메시지가 뜬다. DB 에는 동의 일시(`privacy_agreed_at`)가 저장된다.
- **AC-2** /privacy 페이지가 존재하고 index 하단과 예약 모달에서 링크된다. 수집 항목·목적·보유기간·파기·위탁·권리·책임자·시행일을 포함한다.
- **AC-3** 수업 종류 미선택 시 신청 불가. 선택값이 `lesson_type` 으로 저장된다.
- **AC-4** 토·일 및 설정된 공휴일을 고르면 휴무 안내가 뜨고 시간을 고를 수 없다.
- **AC-5** 시간 목록은 07:00~21:00 이며, 선택한 날짜의 확정 예약(단일+반복)과 50분 이내로 겹치는 시간, 오늘의 지난 시간은 "마감"으로 선택 불가다.
- **AC-6** 휴대번호는 01X-XXXX-XXXX 형식으로 정규화되어 저장되고, 잘못된 형식은 거부된다.
- **AC-7** 요청사항(선택, ≤200자)이 `request_note` 로 저장되고 관리자 카드에 표시된다.
- **AC-8** 예약·취소 규정이 예약 모달과 FAQ 에 표시된다.
- **AC-9** 관리자가 승인/거절하면 안내 문자 모달이 뜨고, 이름·날짜(요일)·시간·수업 종류가 채워진 문구를 수정·`sms:` 전송·복사할 수 있다.
- **AC-10** 승인 시 생성되는 reservations 에는 고객 요청사항을 넣지 않는다(공개 API 노출 방지). 수업 종류만 `class_name` 에 기록한다.
- **AC-11** `node harness/verify.mjs` 오류 0, 기존 기능(공개 배너·FAQ·지도·관리자 예약 달력) 회귀 없음, 모바일 가로 넘침 없음.
