## 1. 요구사항 이해
- 원문: "국내 필라테스 사이트들의 기능들을 조사해주고, 우리사이트에 적용할 수 있는 것들을 찾아 적용해줘"
- 해석: 업계 표준 기능 중 채움(정적 HTML + Supabase + Vercel, 1인 원장 운영 소규모 1:1/1:2 스튜디오)에 **현실적으로 적용 가능한 것**을 골라 구현한다.
- 불명확한 부분: 실제 회원권 가격·환불 규정·보증보험 가입 여부 등 **원장님만 아는 운영 정보**가 필요한 항목이 있다 (→ 7장 질문).

## 4. 제약·리스크
- **운영 DB 변경**: reservation_requests 에 컬럼 추가(수업종류·요청사항·동의일시) 시 SQL Editor 수동 실행 필요. DROP 없는 ALTER 블록으로 처리.
- **anon 노출**: 예약 가능 시간 계산은 시간 정보만 있으면 됨 → anon 컬럼 축소와 함께 설계 가능.
- **알림톡**: 카카오 비즈채널 + 발송대행사 계약 + 서버(Edge Function) + 발신 비용 필요 → 이번 범위에서는 과함. 대안: 관리자 화면에서 `sms:` 링크로 승인/거절 안내 문자를 원클릭 작성(무료, 서버 불필요).
- **회원 로그인/잔여횟수 조회·온라인 결제**: 인증 체계·PG 계약 필요 → 별도 실행 권장.
- **가격·환불 정보**: 원장님 결정 필요한 실제 데이터.

## 7. 승인권자가 결정해야 할 질문
1. 이번 실행 범위를 **A~F** 로 할까요? (G·H 는 다음 실행)
2. **정규 회원권 가격표**를 알려주세요 — 개인/듀엣 × 10·20·30회 가격, 유효기간, 추가비용(기구 사용료 등) 유무.
3. **중도해지 환불 기준**은? (예: 이용 회차 × 정상 1회 단가 + 위약금 10% 공제 후 환불 등 — 현재 계약서 기준)
4. **보증보험 등 피해보상 수단**에 가입되어 있나요? (가입 시 보장기관·기간·금액)
5. **예약 취소 규정**: 몇 시간 전까지 무료 취소, 당일 취소/노쇼 시 회차 차감 여부
6. **휴무 요일·운영 시간**: 토요일 휴무 외에 일요일/공휴일? 수업 가능 시간대(06:00~22:00 그대로?)
7. 개인정보 **보유 기간**: 예약 신청 정보 보관 기간 (예: 처리 후 6개월 / 1년)

> 2~6번 중 답을 아직 정하지 않은 항목은 **설계에서 관리자가 수정 가능한 자리(placeholder 문구 + 관리자 수정 안내)** 로 두고 진행할 수 있습니다.
